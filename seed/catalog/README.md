# seed/catalog: catalog loader (code only, no data)

`make seed-catalog` loads a catalog export into the **local** tf-api Postgres container so portal/funnel/admin
catalog pages have realistic products, offers, Builder placements, coupons, upsell flows and sitemap entries.

- **Data is never committed.** It lives in `.state/catalog-export/data/<table>.json` (gitignored; the script refuses
  to run if that path is not ignored). One JSON array of row objects per table.
- **Allow-list only.** 74 definition tables (products, offers, offer_* joins, images, tags, categories, coupons and
  promo-code *definitions*, campaigns, upsell flows, cancellation reasons, sitemap_entries...). Never customers,
  orders, subscriptions, carts, internal users, redemptions or `feature_flags`. Audit columns pointing at staff
  (`created_by`) are stripped at export time. Tables with any customer linkage are dropped from the export.
- **Local only.** The script runs `psql` inside the compose `postgres` container; `load.sql` also refuses a
  non-local/non-private server address.
- `CATALOG_MODE=replace` (default): one transaction, delete the allow-listed tables in reverse FK order, insert in FK
  order. If a local test order/cart references a catalog row, the delete fails and everything rolls back (no CASCADE).
  `CATALOG_MODE=upsert`: `ON CONFLICT (id) DO UPDATE` / `DO NOTHING`; keeps local rows.
- Handles: Datastream json-as-string columns, generated columns, `search_vector` (rebuilt by triggers), local-only
  nullable columns (left NULL), sequence bump to `max(id)`. Prints `table -> N rows (exported N)` and a final table.

## After loading
- Sitemap: an authenticated local admin `POST /api/v1/sitemaps/generate` on tf-api (perm `sitemap:edit`) writes the
  sitemap from `sitemap_entries` to the local MinIO sitemap bucket.
- Catalog JSON (`nextgen-catalog.json`) is built by tf-api `SyncCatalog`, which runs from a cron (**never run crons
  locally**) or after an admin product create. Not generated by this loader.
- Product/offer image URLs point at the real CDN; the proxy blocks container fetches. Do not add hosts for this.
