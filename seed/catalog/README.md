# seed/catalog: catalog loader (code only, no data)

`make seed-catalog` loads a catalog export into the **local** tf-api Postgres container so portal/funnel/admin
catalog pages have realistic products, offers, Builder placements, coupons, upsell flows and sitemap entries.

- **Data is never committed.** It lives in `.state/catalog-export/data/<table>.json` (gitignored; the script refuses
  to run if that path is not ignored). One JSON array of row objects per table.
- **Customer/order data scan, every load.** `seed/catalog/pii_scan.py` runs before anything is loaded and judges the
  export by its DATA, not by table names. It scans every column and every value (including keys and values nested in
  JSON columns) for customer data (emails, phones, person names, postal addresses, card-like numbers, SSNs, ids that
  point at a person) and order data (order / transaction / charge / subscription / cart ids, order totals, line items,
  shipping and tracking info, "order #" references). A table whose rows carry a populated person-id or order-id
  column is EXCLUDED (loaded as empty); any other column with a hit is DROPPED from every row. Only the cleaned copy
  (`.state/catalog-clean/`, gitignored) is loaded. Output is metadata only (table / column / detector / count; never
  values) in `.state/catalog-clean/SCAN.json`. Tuned to not flag catalog fields (SKUs, product prices,
  `sort_order`, `order_bump_*` config, company role mailboxes like support@, toll-free numbers, image URLs).
  `tests/test-catalog-pii-scan.sh` covers it with synthetic fixtures.
- **Definition tables only at export time.** The export itself is limited to catalog definition tables (products,
  offers, offer_* joins, images, tags, categories, coupons and promo-code *definitions*, campaigns, upsell flows,
  cancellation reasons, sitemap_entries...) and staff audit columns (`created_by`...) are stripped; the scan above is
  the enforcement, so a mistake in the export list still cannot load customer or order data. `feature_flags` is the one
  non-catalog table: a prod snapshot (103 rows, exported read-only via Cerebro, scanned, Michael approved 2026-11-19
  4:59 PM ET; one staff-email value redacted, see `.state/catalog-export/FEATURE_FLAGS.md`). It is always fully
  replaced (also with `CATALOG_MODE=upsert`), and flag values that are prod URLs are rewritten to the local funnels app.
  tf-api runs with `APP_ENV=development` and `make map-flag-env` (run after the load) copies the production rows to
  `development`, so tf-api's environment-scoped lookups see prod values (TFHFUNNEL-8090; `local` rows are impossible:
  the DB trigger rejects them). The name-only lookup the apps use (`/feature-flags/name/...`) also sees prod values.
- **Local only.** The script runs `psql` inside the compose `postgres` container; `load.sql` also refuses a
  non-local/non-private server address.
- `CATALOG_MODE=replace` (default): one transaction, delete the allow-listed tables in reverse FK order, insert in FK
  order. If a local test order/cart references a catalog row, the delete fails and everything rolls back (no CASCADE).
  `CATALOG_MODE=upsert`: `ON CONFLICT (id) DO UPDATE` / `DO NOTHING`; keeps local rows.
- Handles: Datastream json-as-string columns, generated columns, `search_vector` (rebuilt by triggers), local-only
  nullable columns (left NULL), sequence bump to `max(id)`. Prints `table -> N rows (exported N)` and a final table.

## After loading
- Sitemap: an authenticated local admin `POST /api/v1/sitemaps/generate` on tf-api (perm `sitemap:edit`) writes the
  sitemap from `sitemap_entries` to the local MinIO sitemap bucket.
- Catalog JSON (`nextgen-catalog.json`) is built by tf-api `SyncCatalog`, which runs from a cron (**never run crons
  locally**) or after an admin product create. Not generated by this loader.
- Product/offer image URLs point at the real CDN; the proxy blocks container fetches. Do not add hosts for this.
